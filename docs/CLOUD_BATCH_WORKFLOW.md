# Existing batch interface — initial cloud adaptation
Opt-in batch fragment from the original desktop index and CSS; no desktop scripts or JobAdder controls. Select up to ten PDF/DOCX/TXT files, validated before submission, each with its own upload, immutable intent, status and authorized Word download. Sequential admission into existing durable worker queue; server limits remain authoritative (one running job per user). Duplicate names remain separate row identities. An uncertain upload stops the batch; an uncertain submission may be recovered using the same intent only. No automatic retries, no cancellation of paid jobs, no clearing uncertain or active rows. Local row state is cleared on sign-out. No new server batch API or credential exposure. Partial batches stop on uncertainty; after a confirmed recovery, explicitly continue remaining rows with the initially frozen options. Cross-session cross-session history/reconciliation, combined ZIP, formatting summary and full original workflow parity remain pending. Synthetic staging only supports formatting of its exact fictional fixture; blinding uses existing backend contract but is not exercised by fake transport. No production deployment.

# One-time account onboarding foundation
Internal only: authorized owner/admin invites an inactive account with an unknown random placeholder password. Recipient chooses their password by redeeming a cryptographically random single-use token; no session issued automatically. Invitation expires in 24 hours. Reset for an active manageable account immediately invalidates the existing password and sessions, replaces any previous token, and expires in one hour. Only SHA-256 digests are stored, never raw tokens in DB or audit. Credential versions and tenant epochs fence old challenges; transaction locks ensure concurrent redemption succeeds only once. Admin account hierarchy remains in force.
No email delivery or HTTP exposure, user self-service recovery, resend of expired invites, challenge cleanup, or production database role grants yet. An expired reset leaves old credentials invalid; a new administrator-issued reset is required. The initial invite cannot be reissued yet; do not use for real onboarding until recovery is implemented. Token table is a trusted authentication boundary like sessions, not an owner-scoped candidate-data table; production grants must isolate it from workers and ordinary application access. Rate limiting and secure delivery are release blockers. Disposable PostgreSQL tests cover concurrency, replacement, expiry and suspension. No production changes.

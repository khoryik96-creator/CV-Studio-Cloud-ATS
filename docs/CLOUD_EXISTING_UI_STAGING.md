# Original UI composition (staging only)
The opt-in shell composes the original single-CV view and tab markup with the original CSS. It does not replace the desktop source. Only explicitly allowlisted DOM tags/attributes and fixed cloud assets are served; all legacy event handlers, desktop settings, integrations and provider restoration scripts are omitted. Other retained module tabs are shown disabled pending integration. A staging composition root must explicitly mount register_existing_ui(app) after the authenticated CV routes exist. Default cloud app remains closed; this does not enable readiness or deploy the product.

Login, logout, original paste/upload controls, CV job options, status polling, manual same-intent recovery and review-aware downloads are wired through the cloud client. Original structured preview, drag/drop, batch, user preferences, other modules, original branding details and full visual/functional parity are not complete. This deliberately does not mount the full original shell or silently offer unsupported features. Existing UI adapter source and actual rendered markup are tested synthetically, but a real browser/DB/provider staging flow and visual inspection remain release gates. Uses lxml available in the existing full regression dependency set; explicitly add to staging runtime dependencies before deploying. No production data, credentials, paid calls or deployment.

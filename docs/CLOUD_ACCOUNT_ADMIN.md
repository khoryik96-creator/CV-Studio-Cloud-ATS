# Tenant account administration foundation
Internal service for listing, creating, changing role, suspension/reactivation, password reset and explicit session revocation. Server-derived tenant scope; actual active actor role rechecked under transaction lock. Owners manage administrators/recruiters; administrators manage recruiters only. No owner creation, self-modification, destructive deletion or cross-tenant access. Maximum 100 accounts per tenant for initial staging. Role, password and status changes invalidate old credential epochs, and every administration change revokes target sessions and records non-secret action metadata in the same transaction. Optimistic revision checks reject stale edits. Account audit is append-only under non-bypass RLS. Tests use synthetic accounts and disposable PostgreSQL. No HTTP endpoints, email delivery, one-time password workflow, forced password change, user self-service or production grants. Initial passwords must be securely conveyed outside the app; do not use real accounts until onboarding/reset and privileged DB isolation are designed and tested. Previously authorized in-flight operations cannot be guaranteed cancelled by session revocation. No production changes.

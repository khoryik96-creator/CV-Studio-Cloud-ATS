# M1 supervised staging worker runtime
The merged CV runner now renews its lease continuously while executing the engine, checks deadline/loss at processing boundaries, renews before publication, stops heartbeat before final transaction, and relies on SQL fencing for output publication. One active job per owner across database claims (serialized user-row lock). CV-only worker claims never consume queued jobs for the three remaining modules. Expired attempts go to needs_review, not automatic replay.

Explicit trusted roster, round-robin owner/tenant interleaving, bounded local pool of 1–4 jobs (default two), no overlapping rounds per runtime. Provider configuration is resolved before claiming; no paid calls in the resolver. This is an internal staging scheduler round, not a production daemon. Worker threads cannot forcibly cancel native parsers or blocking calls. A trusted deployment composition root, least-privilege discovery/credentials, independent DB connection timeouts, global tenant limits, hard subprocess/container deadlines and resource isolation, safe shutdown and monitoring remain prerequisites. No real credentials, live data, paid calls or deployment.

Cloud PostgreSQL CI now runs on master pushes and manual dispatch as well as PRs. No release until merged-master verification. Synthetic tests added for roster rotation, idle rounds, absent provider configuration and invalid limits.
